# Движок PKI (Public Key Infrastructure) в Vault

## Назначение

Движок PKI в Vault предназначен для управления сертификатами и ключами шифрования:  
- Генерация корневых и промежуточных сертификатов  
- Выпуск, ротация и отзыв сертификатов  
- Управление сроками действия и политиками безопасности сертификатов  

## Основные возможности

- **Выпуск сертификатов (Issuing Certificates)**: автоматическая выдача X.509 сертификатов для сервисов и пользователей.  
- **Ротация сертификатов**: обновление сертификатов по истечении срока действия.  
- **Отзыв сертификатов (Revocation)**: управление списками отозванных сертификатов (CRL).  
- **Настройка политик**: ограничение допустимых значений Subject, SAN, TTL и других параметров.  
- **Интеграция с внешними системами**: поддержка ACME, CA и собственных PKI‑систем.  

## Пример использования

1. Создание корневого сертификата:

```bash
vault secrets enable pki
vault write pki/root/generate/internal common_name="example.com" ttl=8760h
````

2. Настройка URL для выдачи CRL и CA:

```bash
vault write pki/config/urls issuing_certificates="http://vault.example.com:8200/v1/pki/ca" crl_distribution_points="http://vault.example.com:8200/v1/pki/crl"
```

3. Выпуск сертификата для сервиса:

```bash
vault write pki/issue/example-dot-com common_name="service.example.com" ttl="24h"
```

## Рекомендации по использованию

* Использовать PKI для сервисов и пользователей, которым нужна **собственная инфраструктура сертификатов**.
* Не хранить приватные ключи вне Vault.
* Настроить автоматическую ротацию и уведомления о истечении TTL.
* Контролировать доступ через политики Vault.

## Примечание для health-api

В проекте **health-api** PKI‑движок **не используется**, так как:

* Istio уже предоставляет встроенный PKI (mTLS) для сервисов кластера.
* Отдельный PKI через Vault создаёт дублирование и усложняет архитектуру.
* Все сервисные сертификаты автоматически выдаются и ротаются Istio, что покрывает требования безопасности.
