## Описание движка Transit

**Transit Engine** в Vault предназначен для централизованного шифрования и расшифровки данных без необходимости хранить их в Vault. Используется для защиты чувствительной информации, API-ключей, конфигурационных данных и других секретов.

* Не хранит данные, только ключи
* Поддержка симметричного шифрования, HMAC, подписи и декодирования
* Позволяет управлять версиями ключей и ротацией

---

## Основные возможности

* **Шифрование/Расшифровка**: безопасная работа с данными без их хранения в Vault
* **Подписи и проверка**: генерация цифровых подписей и их верификация
* **HMAC**: проверка целостности сообщений
* **Ротация ключей**: управление версиями и автоматическая смена ключей
* **Audit logging**: фиксирование всех операций

## Пример конфигурации

```bash id="v2n0xb"
# setup-transit-engine.sh
vault secrets enable transit

# Создание ключа для backend
vault write -f transit/keys/backend-key \
    type=aes256-gcm96 \
    exportable=false \
    allow_plaintext_backup=false \
    derived=true

# Создание ключа для frontend
vault write -f transit/keys/frontend-key \
    type=aes256-gcm96 \
    exportable=false \
    allow_plaintext_backup=false \
    derived=true
```

## Использование для шифрования данных

* Шифрование строки:

```bash id="k8l3bt"
vault write transit/encrypt/backend-key plaintext=$(base64 <<< "секретные данные")
```

* Расшифровка строки:

```bash id="u9v4kj"
vault write transit/decrypt/backend-key ciphertext="vault:v1:ABC123..."
```

* Генерация подписи HMAC:

```bash id="h5r7nm"
vault write transit/hmac/backend-key input=$(base64 <<< "сообщение")
```

* Проверка подписи:

```bash id="g2t8pl"
vault write transit/verify/backend-key input=$(base64 <<< "сообщение") hmac="vault:v1:XYZ456..."
```

## Рекомендации по безопасности

* Всегда использовать TLS для подключения к Vault
* Настроить ротацию ключей по графику
* Разграничивать доступ к ключам через политики Vault
* Включить audit logging для всех операций
* Не использовать экспортируемые ключи для продакшена
